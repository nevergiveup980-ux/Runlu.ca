From a shopping shelf to an everyday list

The earliest use case was shopping: items repeat, quantities change, and a familiar item should not have to be typed from scratch each time. That practical test led to a broader question. Why should the same lightweight pattern stop at groceries? The product direction became a universal list, with shopping kept as a complete first scenario rather than the whole definition.

What should disappear, and what should stay?

A finished task belongs in Done, but its useful name may belong in Memory. Those are different kinds of information. Keeping them separate lets a fresh list feel clean while allowing Quick Picks and autocomplete to reduce repeated typing. Local-first storage also keeps the core experience independent of a required account.

The cost of one extra feature

Every new control asks the user to learn something. Duplicate Guard and smart quantities are worthwhile only if they remove friction. The same test applies to labels, dashboards and elaborate planning tools: a simple list should not become a second job. This is a design direction, not a claim that every edge case has been solved.

Today and Done keep current tasks simple. Local Memory and Quick Picks make familiar entries easier to reuse. Duplicate protection, quantities and autocomplete matter only when they save effort.

By October 2026, RUNLU LIST had passed Apple review. Approval is not the same as a public App Store release.

从购物货架走向日常列表

最初的使用场景是购物：常买的东西会重复出现，数量会变化，同一个名称不应该每次都从头输入。这个具体场景又引出一个问题：既然这种轻量方式能用于购物，为什么不能用于其他日常事务？于是，产品方向从购物清单走向通用列表；购物仍是第一个完整支持的场景，却不再是产品的全部定义。

什么应该消失，什么应该留下？

做完的事情可以进入 Done，但曾经输入过的常用名称，仍可能值得留在 Memory。这是两种不同的信息。把它们分开，既能让新清单保持干净，也能通过 Quick Picks 和自动补全减少重复输入。本地优先的设计，则让核心体验不必依赖账户。

多加一个功能，也有代价

每增加一个按钮，使用者就多一件需要理解的事情。Duplicate Guard 和智能数量只有在确实减少麻烦时才有价值。复杂标签、看板和规划功能也应接受同样的检验：清单不该成为另一份工作。这是一条设计方向，并不意味着所有边界情况都已解决。

Today 和 Done 保持眼前任务清楚；本地 Memory 和 Quick Picks 让常用项目无需反复输入。重复项保护、数量处理与自动补全，只有真正节省操作时才值得留下。

Des courses aux listes du quotidien

Les courses ont fourni un premier test concret : les mêmes articles reviennent, les quantités changent et personne ne souhaite tout ressaisir. Cette logique pouvait servir au-delà des achats. RUNLU LIST a donc pris la direction d’une liste universelle, tout en conservant les courses comme premier scénario complet.

Ce qui s’efface et ce qui reste

Une tâche terminée peut rejoindre Done, tandis que son nom utile peut rester dans Memory. Cette séparation garde la liste actuelle claire et permet à Quick Picks et à l’autocomplétion de réduire les répétitions. Le choix local-first évite de rendre un compte obligatoire pour les fonctions essentielles.

Chaque fonction a un coût

Chaque bouton supplémentaire demande un apprentissage. Duplicate Guard et les quantités intelligentes ne sont utiles que s’ils simplifient le geste. Une liste ne devrait pas devenir un travail en soi. Il s’agit d’une direction de conception, pas d’une promesse que tous les cas particuliers sont résolus.

Today et Done clarifient les tâches. Memory local et Quick Picks facilitent la réutilisation. Les autres fonctions ne comptent que si elles économisent des gestes.

En octobre 2026, RUNLU LIST avait passé la vérification d’Apple. L’approbation ne signifie pas une sortie publique.

Las compras ofrecieron la primera prueba práctica: los productos se repiten, las cantidades cambian y no conviene escribir lo mismo desde cero. Esa lógica también podía servir fuera del supermercado. RUNLU LIST evolucionó hacia una lista universal, manteniendo las compras como primer escenario completo.

Lo que se borra y lo que permanece

Una tarea terminada puede pasar a Done, mientras que su nombre útil puede permanecer en Memory. Separar ambas cosas mantiene limpia la lista actual y permite que Quick Picks y el autocompletado reduzcan la repetición. El enfoque local-first evita exigir una cuenta para las funciones esenciales.

Cada función tiene un costo

Cada botón nuevo exige aprendizaje. Duplicate Guard y las cantidades inteligentes solo merecen estar si simplifican el uso. Una lista no debería convertirse en otro trabajo. Es una dirección de diseño, no una afirmación de que todos los casos especiales estén resueltos.

Today y Done aclaran las tareas. Memory local y Quick Picks permiten reutilizar elementos. Las demás funciones solo importan si ahorran pasos.
