RUNLU · Engineering Reliability

We don’t just test whether it works. We test how it fails.

Reliability is treated as evidence, not a marketing adjective. Meaningful changes are tested, repeated, stressed, and traced before they are allowed to become a release.

Every meaningful change must be testable, repeatable, and regression-safe.

Release discipline

A failed critical gate means no release.

The long-term release rule is simple: a meaningful release must pass its required regression gates. A defect discovered once should become a permanent test wherever practical.

Detect → Quarantine → Reconcile → Verify.
When data is wrong, RUNLU’s design direction is to preserve evidence and make corrective action explicit—not silently rewrite history.

发布纪律

关键测试不过，不发布。

长期原则很简单：任何有实质影响的版本，都必须通过相应的回归门槛。一个重要缺陷一旦被发现，在条件允许时就应变成永久回归用例。

发现异常 → 隔离异常 → 明确对账 → 再次验证。
数据出错时，RUNLU 的设计方向不是偷偷把历史改掉，而是保留证据，让修复动作明确、可追踪。
