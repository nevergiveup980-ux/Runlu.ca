RUNLU License Core

In September 2026, RUNLU established its first reusable licensing foundation for independently distributed software — separating possession of a downloadable file from the right to activate and use the software.

September 2026 · RLC foundation established
Pilot passed

From a download to a licensed product.

A license file can state what a customer may do. RUNLU License Core adds a technical layer that can enforce important parts of that agreement while preserving practical offline use.

Purchase-linked entitlementA legitimate RUNLU purchase can establish the customer's software entitlement.
Controlled device activationA license can allow a defined number of active devices rather than unlimited copying.
Offline-ready operationAfter successful activation, a local receipt can preserve licensed use without requiring a permanent network connection.
Customer-managed releaseCustomers can release an old activation and recover a device slot for another device.
Server-side revocationReleased activations can be invalidated when the software next verifies its status online.
Atomic activation limitsActivation capacity is enforced as a single protected operation so simultaneous requests cannot legitimately exceed the configured limit.

The test that improved the system.

During the pilot, repeated activation, release, browser, device, and offline tests exposed a concurrency edge case: a three-device license briefly reached four active records. Instead of treating the display as the problem, the activation path was redesigned at the database boundary. Capacity checking and activation were made atomic, the excess pilot record was released, and the license returned to its intended three-of-three state.

Engineering principle
Do not hide an invariant violation in the interface. Fix the layer that allowed the invariant to break.

The pilot also verified the practical lifecycle around the license: activation, reaching the device ceiling, rejecting an additional device, releasing an activation, reactivating when capacity becomes available, maintaining an offline-ready receipt, and recognizing a released activation when online verification resumes.

A RUNLU platform layer.

RLC was born while testing RUNLU NEXT, but it is intentionally broader than one product. The foundation is designed to be reusable by future independently distributed RUNLU software, so each product does not need to invent its own licensing system.

This public record describes capabilities and lessons, not security-sensitive implementation details. Internal identifiers, token construction, fingerprints, database structure, and operational secrets are intentionally omitted.
