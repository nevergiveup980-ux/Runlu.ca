User manual · workflow-first

How to use Deerfoot Flooring OS

Use this manual as a daily operating guide. The system follows the real movement of an Order, material, people and money. Start with the work in front of you; the software should help you find the next action.

1. Start & Navigation

The main navigation is the shortest route to daily work: Command · Orders · PO · Warehouse · Invoice · Operations · Service / Claims · Accounting · Settings. Showroom and Estimate / Assessment are also available from Command.

Open Command first. Check the active Order and any attention items.
Select the correct Order before editing a downstream module. PO, Invoice, Operations and Accounting are designed to follow the active Order.
Use source records whenever possible. Calendar and Accounting are views/control layers over the business data; do not create duplicate side records unless the module explicitly calls for them.
Version safety: V0.3.63 remains the explicit stable rendering rollback baseline. Documentation reflects V0.3.68 and the workflow layers through V0.3.67.1.

2. Orders · the digital file drawer

Orders replace the old “Jobs” wording in the user interface. Internally, some legacy field names still use jobId/jobNumber for compatibility.

ACTIVE ORDERSBACK ORDERSPEOPLE TO CALL

Find an Order

Use Customer / Company, phone, Order #, Invoice # or PO #. The two drawers automatically file numeric-leading customer/company names first, then natural A–Z.

Create or edit an Order

Choose + New Order.
Enter Order #, customer, contact information, addresses, clerk/sales reference, required date and items.
Save before creating linked PO, Invoice or operational records.
Use status and fulfillment fields to reflect reality; do not move an Order simply to make the screen look tidy.

Active vs Back

DrawerMeaningTypical next step
ActiveMaterial/work is ready enough to move toward customer pickup, delivery or installation.Fulfill, schedule, invoice or close.
Back OrderMaterial is still pending, including supplier pickup/delivery or partial receipt.Procure, receive, review shortage.
Manual Move Active / Move Back is an override. Use it only when the real physical file would also move between the two drawers.

3. PO / Supplier Orders & Supplier Pickup

Create / maintain a supplier PO

Open the correct Order first.
Go to PO and create/select the supplier order.
Confirm supplier, PO #, items, quantities, requested/expected date and fulfillment method.
Choose the real inbound route: Supplier Pickup when Deerfoot goes to the supplier, or Delivery / Freight when the supplier/carrier delivers to Deerfoot.
Keep PO status aligned with what has physically happened.

Supplier Pickup folders

Supplier Pickup is deliberately separate from the Orders drawer. Use Today · This Month · Recent Months · All, plus the supplier/trip planner, to prepare truck runs.

Terminology: Supplier Pickup is inbound procurement. Customer Pickup is outbound fulfillment. They are different workflows even though both use the word “pickup.”
Do not mark Received/Completed before physical receiving. Downstream readiness, People TO Call and Accounting Match depend on PO/receiving status.

4. Receiving & Warehouse

Receiving is the bridge between purchasing and fulfillment. Warehouse should confirm what physically arrived, not what was expected to arrive.

Match the shipment/pickup to the PO and Order.
Confirm quantity and any partial/backordered lines.
Receive material and place it into the proper warehouse workflow/location.
For partial receipt, keep the remaining material visibly pending.
Once material is ready, the Order can progress toward Active / customer fulfillment.

The embedded RUNLU Warehouse OS handles warehouse-specific inventory, cut, transfer, shipping/return and location workflows.

Current People TO Call trigger: supplier-pickup POs marked Received/Completed are treated as received for the sales queue. A future dedicated Put Away source field can make this even stricter.

5. People TO Call

People TO Call is a Sales action queue created after Supplier Pickup material has been received. It is not an inventory state.

Open Orders and find the gold People TO Call area.
Review customer, Order #, source Pickup PO, received date and Sales/Clerk.
Update status: Not Called → Called → Waiting Customer → Done.
After the next step is agreed, use Move Active & Done when appropriate.
Then route the Order to Customer Pickup, Delivery or Operations / Installation.
An Order can be materially ready but still remain in People TO Call because the human sales follow-up has not been completed.

6. Operations, Calendar & People

Assign work

Use the source Order/Operations form to set installer, install date, start/end time, status, address and notes. Calendar Direct Edit can edit the same record visually.

Calendar

Available views include Scheduler, Day, 3 Days, Week, 4 Weeks, Month, Year, Agenda, List and Tiles. Groups can be shown/hidden and include installers, pickup/receiving, deliveries, appointments/measurements and CHC/other.

Visual signalMeaning
Bar shape / spanSchedule duration, including multi-day continuation.
Internal progressBusiness stage / work progress.
Bottom railMaterial readiness.
Corner flagConflict, hold or issue.

People Manager

Use People to Add, Edit, Deactivate or Reactivate personnel. Deactivate instead of deleting so historical Orders and calendar events keep their original assignments. One person can belong to more than one group (Installer, CHC, Sales, Appointments, Measurements).

7. Invoice & Payments

Generate the Deerfoot invoice

Select the correct Order.
Open Invoice or use Generate / Update Invoice from the Order/Accounting flow.
Verify Sold To / Ship To, items, subtotal, GST, payment and balance.
Use the three-copy output logic: customer white copy, warehouse yellow copy, accounting pink copy.
Print only after checking the active Order and totals.

Credit-card fee

The current company-policy layer applies a separate 2.5% non-taxable credit-card fee to eligible Orders dated September 1, 2026 onward, while GST remains based on the taxable project amount. Accounting can waive/override with a reason.

Accounting review required: company card-surcharge policy should remain aligned with the processor/card-network and Canadian rules. The software rule is not a substitute for policy/legal review.

Payments

Record deposits and later payments through the shared payment lifecycle. The balance should follow the same active Order and invoice; avoid keeping a separate informal balance outside the system.

8. Accounting Control

Accounting uses an exception-first control language rather than forcing every user to start with journal-entry terminology.

GREEN · Clear / MatchedGOLD · Action / ReviewRED · Exception / OverdueBLUE · Financial / TaxGRAY · Closed / Not Connected

Accounting Control board

Review Receivable, Payable, GST Estimate, Job Profit, Attention and Bank status. Bank remains clearly marked not connected until a real feed/reconciliation source is implemented.

Attention

Work the exceptions first: overdue A/R, PO/vendor-bill variance, missing ITC documentation, receiving/bill mismatch, WCB/T5018 review or other unresolved controls.

Match

Use PO ↔ Receiving ↔ Vendor Bill to decide whether a payable is safe to proceed. A matched amount is green; incomplete receiving or amount variance requires review.

Financial Trail

Trace the business history instead of guessing where a number came from:

Foundation tabs

Job CostingMaterial, installer/labour, freight, prep, overhead, commission and other cost buckets; gross margin.

9. Service / Claims

Select the original Order.
Open Service / Claims.
Enter claim/service #, type, status, opened date, supplier, related PO, assigned inspector, recovery credit and notes.
Use the status to reflect the real path: Open, Inspection Scheduled, Waiting Supplier, Approved, Credit Pending, Resolved, Closed.
Keep recovery credits and final resolution tied to the original Order so Accounting and customer history remain traceable.

12. Data, safety & troubleshooting

Browser / device storage

Several current modules still use browser-local operational storage. Do not assume a record created on one device is automatically present on every other device unless that module has a confirmed shared backend.

Before critical changes

Confirm the active Order, customer and PO. For Receiving, payment, invoice, Accounting or claim adjustments, use the real source document as the check.

Safari / cached builds

The V0.3.63 unified render gate is the stable Safari baseline. If a newer page appears stale, reload the production Flooring URL instead of opening an old cached version link. Avoid repeatedly opening multiple old Calendar builds in separate tabs during testing.

Financial and legal information

Do not use the system as the sole source for statutory filings until central persistence, backup, audit retention, bank/GL integration and professional controls are complete.

Never “fix” a workflow by inventing a status. If the real business does not have a reliable source field yet (for example a dedicated Put Away confirmation), keep the limitation visible and improve the source data later.

Deerfoot Flooring OS 怎么用

把这份手册当作日常操作指南。系统追踪的是同一个 Order、材料、人和钱在公司里怎样一步一步往前走。先看眼前真实要做的事情，再让系统告诉你下一步。

1. 开始与导航

主导航对应日常最常用的工作：Command · Orders · PO · Warehouse · Invoice · Operations · Service / Claims · Accounting · Settings。Showroom 和 Estimate / Assessment 可以从 Command 进入。

每天先看 Command。确认当前 Active Order 和 Attention。
进入下游模块前，先确认当前选中的 Order。 PO、Invoice、Operations、Accounting 都会跟随这个 Order。
尽量编辑 source-of-truth。 Calendar 和 Accounting 是业务记录的视图/控制层，不要另造一套重复数据。
版本安全：V0.3.63 继续是明确的稳定渲染回滚基线。本手册对应 V0.3.68，并覆盖目前到 V0.3.67.1 的主要工作流。

2. Orders · 数字文件抽屉

用户界面正式以 Orders 为主要叫法。为了兼容既有模块，底层还有一些字段继续叫 jobId / jobNumber。

ACTIVE ORDERSBACK ORDERSPEOPLE TO CALL

找 Order

可以按 Customer / Company、电话、Order #、Invoice #、PO # 搜索。两边抽屉会自动把数字开头的客户/公司排最前，再按自然 A–Z 排列。

新建或编辑

点 + New Order。
输入 Order #、Customer、联系方式、地址、Clerk/Sales、Required Date 和 Items。
创建 PO、Invoice 等关联记录以前先保存。
Status 和 fulfillment 应反映真实情况，不要为了页面好看随便搬状态。

Active 与 Back

抽屉真实含义常见下一步
Active材料/工作已基本 ready，可以进入 Customer Pickup、Delivery 或 Installation。出货、安排、开票、结单。
Back Order仍在等材料、Supplier Pickup/Delivery、partial receiving 等前置条件。采购、收货、处理缺料。
Move Active / Move Back 是人工 override。只有当现实里的纸质文件也应该搬到另一边抽屉时才使用。

3. PO / Supplier Orders 与 Supplier Pickup

建立供应商 PO

先选正确 Order。
进入 PO，建立或打开 Supplier Order。
核对 Supplier、PO #、items、quantity、requested/expected date 和 fulfillment。
真实 inbound route 是：Deerfoot 自己去取货就选 Supplier Pickup；供应商/货运送到 Deerfoot 就是 Delivery / Freight。
PO Status 必须跟实际发生的事情一致。

Supplier Pickup 文件夹

Supplier Pickup 保持独立于 Orders。按 Today · This Month · Recent Months · All 看取货文件，并可按 Supplier / Trip Plan 规划卡车行程。

术语一定要分清：Supplier Pickup 是 inbound procurement；Customer Pickup 是 outbound fulfillment。
没有真正收货以前不要标 Received / Completed。 后面的 material readiness、People TO Call 和 Accounting Match 都依赖这个状态。

4. Receiving 与 Warehouse

Receiving 是 Purchasing 与 Fulfillment 之间的桥。Warehouse 应确认“实际到了什么”，而不是“本来应该到什么”。

把货物与正确 PO、Order 对上。
确认数量以及 partial/backorder。
完成 Receiving，并进入正确的 warehouse/location 流程。
如果只到一部分，剩余部分继续保持 pending。
材料 ready 后，Order 才进入 Active / 客户履约方向。

内嵌 RUNLU Warehouse OS 继续负责库存、cut、transfer、shipping/return、location 等仓库专用工作。

当前 People TO Call 触发方式：Supplier Pickup PO 被标为 Received/Completed 后视为已经收货。以后如果有正式 Put Away source field，再把条件收紧。

5. People TO Call

People TO Call 是 Supplier Pickup 收货后产生的 Sales 工作队列，不是库存状态。

在 Orders 页面找到金色 People TO Call。
查看 Customer、Order #、Pickup PO、Received Date、Sales/Clerk。
按真实进度更新：Not Called → Called → Waiting Customer → Done。
确认下一步后，合适时点 Move Active & Done。
再进入 Customer Pickup、Delivery 或 Operations / Installation。
材料可以已经 ready，但只要 Sales 还没完成跟进，这个 Order 仍然可以停在 People TO Call。

6. Operations、Calendar 与 People

安排施工

在源 Order / Operations 表单里设置 Installer、Install Date、Start/End Time、Status、Address、Notes。Calendar Direct Edit 修改的是同一份业务记录。

Calendar

视图包括 Scheduler、Day、3 Days、Week、4 Weeks、Month、Year、Agenda、List、Tiles。Groups 可以显示/隐藏 Installer、Pickup/Receiving、Deliveries、Appointments/Measurements、CHC/Other。

视觉信号含义
Bar shape / span安排的时间跨度、多天延续。
内部进度业务阶段 / 完成进度。
Bottom rail材料 readiness。
Corner flagConflict、Hold 或 Issue。

People Manager

可以 Add、Edit、Deactivate、Reactivate。人员离开时优先 Deactivate，不要硬删除，这样旧 Order / Calendar 历史仍能保留原分配。一个人可以属于多个 group。

7. Invoice 与 Payments

生成 Deerfoot Invoice

先确认 Active Order。
进入 Invoice，或者从 Order/Accounting 更新 Invoice。
核对 Sold To / Ship To、items、Subtotal、GST、Payment、Balance。
三联输出：客户白色、Warehouse 黄色、Accounting 粉色。
打印前再次确认 Order 和金额。

信用卡费用

目前系统按 Deerfoot 公司政策：2026-09-01 及以后符合条件的信用卡订单增加独立 2.5% non-taxable fee，GST 仍只按 taxable project amount 计算；Accounting 可以 Waive/Override 并记录理由。

需要 Accounting 复核：公司的 card surcharge 政策仍应持续与 processor / card-network 及加拿大相关规则保持一致，系统配置本身不能代替政策/法律确认。

Payment

Deposit 和后续 payment 应进入共享 payment lifecycle，让 balance 跟同一个 Order / Invoice 走，避免再在系统外维护一套“口头余额”。

8. Accounting Control

Accounting 采用 exception-first，而不是一上来就要求普通员工理解 Journal Entry / Debit / Credit。

绿色 · Clear / Matched金色 · Action / Review红色 · Exception / Overdue蓝色 · Financial / Tax灰色 · Closed / Not Connected

Accounting Control

先看 Receivable、Payable、GST Estimate、Job Profit、Attention、Bank。Bank 在真正接入前明确显示 Not Connected，绝不伪造余额。

Attention

优先处理真正异常：A/R overdue、PO/Vendor Bill variance、ITC documentation 缺失、Receiving/Bill 不一致、WCB/T5018 Review 等。

Match

通过 PO ↔ Receiving ↔ Vendor Bill 判断供应商账单是否足够一致。金额对上显示绿色；Receiving 不完整或金额有差异就要求 Review。

目的是让人能追问：“这笔钱从哪里来的？”而不是只看到一个最终数字。

12. 数据、安全与排错

设备与 Browser Storage

当前若干模块仍使用 browser-local operational storage。某台设备上有的数据，不应该想当然认为其它设备也一定已有，除非那个模块已经确认接入共享 backend。

关键动作以前

先确认 Active Order、Customer、PO。Receiving、Payment、Invoice、Accounting、Claim 调整时，要拿真实 source document 再核一次。

Safari / Cache

V0.3.63 Unified Render Gate 是稳定 Safari 基线。如果页面看起来像旧版，优先重新进入 production Flooring URL，不要继续使用旧版本缓存链接。测试 Calendar 时也不要同时开很多历史 build。

财务与法律数据

中央数据库、备份、audit retention、Bank/GL integration 和专业控制完成之前，不要把本系统当成唯一 statutory filing source。

不要为了“让流程通”而编造业务状态。如果现实里还没有可靠 source field（比如专门 Put Away confirmation），就把限制如实显示，后面再补 source data。
